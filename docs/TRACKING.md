# 0.7 beta — physical trajectory replay

This is an explicit feedback-controlled replay, not trajectory optimal control or a general animation generator. The existing `solve` command builds a kinematic target; `track` consumes that result with the same body profile and retains the original author keys and timeline. Cubic translation/hinge splines and SO(3) rotation splines supply target position, velocity and acceleration. Target FK and exact hinge/fixed DOFs are validated; incompatible targets are rejected rather than silently projected. Initial configuration and velocity come from the target; they are not optimized.

The controller uses acceleration feedforward plus PD joint error in the neutral-parent basis. Inverse dynamics at the current simulated state generates generalized moments, with explicit clipping to declared actuator caps. On a floating base, the root acceleration is solved from the unactuated root block of the coupled mass matrix; all six root actuation components are exactly zero. Root tracking is not promised. Fixed base means an external fixture. Known world loads can be explicitly supplied; no hidden root wrench. Midpoint integration recomputes the controller at the midpoint. Gains are heuristic, with basic explicit step-size guards, not a proof of stability. Failure stops integration and returns partial evidence, not a complete solved clip. Saturation requires review even if the keys happen to match.

```
python solver.py track body.json solved.json tracking_options.json tracked.json
```

Options: `{"schema":"kineforge.tracking.v1","fixedBase":false,"substeps":4,"kp":100,"kd":20,"maxKeyErrorMm":10,"maxTargetAngleDeg":5}`. `kp` and `kd` are acceleration-feedback gains (s^-2 and s^-1); `externalLoads` use the coupled scenario format. Substeps 1–64 per source interval. Explicit nonempty support schedules are rejected; empty/absent contacts mean no support in this mode. No contact force allocation, impact, sliding, automatic discovery or optimized initial velocities. The legacy contact/collision analysis still exists in `solve`; `track` is not a replacement. Optional collisionModel is checked on the exported shortest-arc pose path only, not continuous integration or response. No contact-aware inner tracking loop yet.

Output includes `report`, `frames` (states, generalized actuation, momentum/energy, equation residual), `dof`, and `solved` (editor-compatible object for completed runs only, even if REVIEW_REQUIRED). OriginalAuthorKeys and timing remain unchanged. `TRACKING_CANDIDATE` means sampled replay succeeded within specified key and orientation tolerances, without detected saturation or declared proxy collision; not physical or game acceptance. `REVIEW_REQUIRED` carries flags and errors. The initial kinematic target is not itself assumed to be accepted. Never distribute a rejected clip as a playable patch. Rotation targets derived from positions alone have unobservable twist; the controller tracks supplied rotations, it does not infer biological anatomy.

Reproduce `python -m unittest discover -s tests -v` and `python examples/tracking_benchmark.py tracking_benchmark.json`. Fixed-base polynomial target convergence, free ballistic tracking, impossible hovering, internal recoil, cap saturation and invalid targets are covered. Private character evaluation is outside public fixtures. Remaining: contact-aware actuator estimation, joint feasibility-aware target generation, full motion optimization and independent character holdouts.

## Gamma extension
The Beta no-contact contract above remains the baseline. For optional explicit scheduled sticking supports use `supportSchedule` in tracking options, as described in [SUPPORT.md](SUPPORT.md). The statements above about lack of contact tracking refer to Beta only.
